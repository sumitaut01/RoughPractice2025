1. Overview

System is a final class in java.lang that provides access to system-level resources and operations — standard I/O streams, environment variables, system properties, timing, array copying, and JVM-level utilities like garbage collection hints and shutdown.

Why it's final: it's a core utility class meant to expose a fixed, controlled API to the underlying platform. Allowing subclassing would let someone override system-critical behavior — Java prevents that by design.

Why the constructor is private: every member is static, so there's no reason to instantiate it — instantiation is explicitly disallowed.

// This will NOT compile:
System s = new System(); // constructor is private

2. Standard Streams — the three public static final fields

FieldTypePurpose
System.inInputStreamStandard input (keyboard / piped input)
System.outPrintStreamStandard output (console)
System.errPrintStreamStandard error (unbuffered, for error/log output)

Redirecting streams

PrintStream fileOut = new PrintStream(new FileOutputStream("log.txt"));
System.setOut(fileOut);   // redirect System.out to a file
System.setErr(fileOut);   // redirect System.err similarly
System.setIn(new FileInputStream("input.txt")); // redirect stdin

QA/automation angle: useful when capturing console output of a process under test, or silencing noisy third-party logs to a buffer during a test run.

3. Timing Methods

currentTimeMillis()

Wall-clock time in milliseconds since the Unix epoch. Good for timestamps, but not reliable for measuring elapsed duration since it can jump (NTP sync, manual clock changes).

nanoTime()

High-resolution, monotonic time source in nanoseconds — has no relation to wall-clock time, only meaningful for measuring elapsed intervals. Always preferred for benchmarking/timeouts.

long start = System.nanoTime();
runOperation();
long elapsedMs = (System.nanoTime() - start) / 1_000_000;
System.out.println("Took " + elapsedMs + " ms");
Why not use currentTimeMillis() for measuring performance?
It's tied to the system clock, which can be adjusted forward/backward (NTP sync, DST, manual change), producing negative or skewed durations. nanoTime() uses a monotonic clock source unaffected by wall-clock changes.

4. arraycopy() — native, high-performance array copy

static void arraycopy(Object src, int srcPos,
                       Object dest, int destPos, int length)
int[] source = {1, 2, 3, 4, 5};
int[] dest = new int[5];
System.arraycopy(source, 0, dest, 0, source.length);
// dest = [1, 2, 3, 4, 5]

It's implemented natively (JNI), so it's significantly faster than a manual loop for large arrays. It's also what Arrays.copyOf() and ArrayList's internal resizing use under the hood.

Handles overlapping ranges correctly — unlike a naive manual copy loop, which can corrupt data when source and destination overlap.

String javaVersion = System.getProperty("java.version");

Property vs environment variable — what's the difference?
System properties are JVM-level, settable at runtime with -D flags or setProperty(). Environment variables come from the OS process environment, are read-only from Java, and are typically set before the JVM starts (shell, CI pipeline, Docker env, etc.).

QA/automation angle: reading getProperty("os.name") to branch cross-platform Selenium driver setup, or reading env vars for environment-specific base URLs / credentials in a test framework.

6. exit(), gc(), identityHashCode(), lineSeparator()

System.exit(int status)

Terminates the JVM immediately. 0 conventionally means success, non-zero means abnormal termination. Triggers registered shutdown hooks before the JVM actually dies.

System.exit(0);   // normal termination
System.exit(1);   // error termination

System.gc()

Only a suggestion to the JVM to run garbage collection — not a guarantee. The JVM is free to ignore it. Rarely used in production code; mostly seen in memory-profiling/benchmark scenarios.

System.identityHashCode(Object obj)

Returns the default hash code an object would have (as from Object.hashCode()), even if the object's class overrides hashCode(). Useful for identity comparisons/debugging.

System.lineSeparator()

Returns the platform-specific line separator (\n on Linux/Mac, \r\n on Windows) — preferred over hardcoding "\n" for portability.

8. What is JNI? (Java Native Interface)

JNI is the framework that lets Java code call native code written in C/C++, and lets native code call back into the JVM. It's the bridge between Java's managed, platform-independent world and platform-specific native libraries — and it's exactly what System.load() / System.loadLibrary() plug into.

Why it exists

ReasonExample
Access OS-specific featuresLow-level hardware access, OS APIs Java doesn't expose
Reuse existing native codeLegacy C/C++ libraries instead of a full Java rewrite
Performance-critical pathsNative execution for hot code (less relevant now with JIT)

How it works

  1. Declare a method with the native keyword — signature only, no body.
  2. Implement it in C/C++ following JNI's calling conventions.
  3. Compile it into a shared library: .so (Linux), .dll (Windows), .dylib (Mac).
  4. At runtime, System.loadLibrary() loads it and links the native implementation to the Java stub.
public class NativeExample {
    static {
        System.loadLibrary("myNativeLib"); // loads mynativelib.so / .dll
    }
    public native int computeFast(int x); // implemented in C, no Java body
}

Trade-offs

Harder to debug across the Java/native boundary, platform-specific (separate builds per OS/architecture), and a crash in native code can bring down the entire JVM — no exception safety net like pure Java code has.

Q: How does System.loadLibrary() relate to JNI?
A: It's the runtime loading step of JNI — it locates and loads the compiled native shared library (.so/.dll/.dylib) and links its native function implementations to the corresponding native method stubs declared in Java.

9. Interview Q&A Quick-Fire

Q: Why is System a final class with a private constructor?
A: All members are static, so there's no need to instantiate it, and making it final/non-subclassable prevents altering core system-facing behavior.
Q: How would you measure the execution time of a method accurately?
A: Use System.nanoTime() before and after, and take the difference — not currentTimeMillis(), since that's tied to the (adjustable) wall clock.
Q: What's the fastest way to copy elements between two arrays in Java?
A: System.arraycopy() — it's a native method, faster than a manual for-loop, and safely handles overlapping source/destination ranges.
Q: Does calling System.gc() guarantee garbage collection runs?
A: No — it's only a hint to the JVM. The JVM may choose to ignore the request entirely.
Q: How do you pass a custom system property to a running Java application?
A: Via the -D JVM flag at startup, e.g. java -Dmyapp.env=staging -jar app.jar, then read it with System.getProperty("myapp.env").
Q: Can you redirect System.out to a file at runtime?
A: Yes — construct a PrintStream wrapping a FileOutputStream and pass it to System.setOut(...).
