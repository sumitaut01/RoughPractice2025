1. Why EnumMap / EnumSet exist

You could always use a HashMap<MyEnum,V> or HashSet<MyEnum>. They'd work correctly. But enums have a property ordinary keys don't: a fixed, known-in-advance set of values, each with a stable ordinal() index. EnumMap/EnumSet exploit that to trade the general-purpose hashing machinery for a flat array indexed by ordinal — faster, more compact, and iterates in enum declaration order instead of hash order.

Rule of thumb: if your key or element type is an enum, EnumMap/EnumSet should be your default choice over HashMap/HashSet — it's strictly better for that use case, with no downside.

2. EnumSet

A Set implementation exclusively for enum types, backed internally by a bitmask (a long, or an array of longs if the enum has >64 constants).

enum Day { MON, TUE, WED, THU, FRI, SAT, SUN }

public class EnumSetDemo {
    public static void main(String[] args) {

        // 1. Factory methods — no public constructor exists
        EnumSet<Day> weekdays = EnumSet.range(Day.MON, Day.FRI);
        EnumSet<Day> weekend  = EnumSet.of(Day.SAT, Day.SUN);
        EnumSet<Day> none     = EnumSet.noneOf(Day.class);
        EnumSet<Day> all      = EnumSet.allOf(Day.class);
        EnumSet<Day> notWed   = EnumSet.complementOf(EnumSet.of(Day.WED));

        // 2. Set algebra reads naturally
        weekdays.removeAll(EnumSet.of(Day.FRI)); // remove Friday
        System.out.println(weekdays);            // [MON, TUE, WED, THU]

        // 3. Iteration order == declaration order, always
        for (Day d : all) System.out.print(d + " ");
        // MON TUE WED THU FRI SAT SUN

        // 4. Bulk ops are bitwise under the hood -> very fast
        boolean isWorkday = weekdays.contains(Day.TUE); // O(1), single bit test
    }
}

Classic use case: replacing bit-flag int constants. Instead of int PERMS = READ | WRITE; with hand-rolled bitmasks, use EnumSet<Permission> — same performance, type-safe, readable, no magic numbers.

3. EnumMap

A Map implementation exclusively for enum keys, backed internally by a plain array sized to the number of enum constants — indexed directly by key.ordinal().

enum Status { NEW, IN_PROGRESS, REVIEW, DONE }

public class EnumMapDemo {
    public static void main(String[] args) {

        // Constructor needs the enum's Class object (for array sizing)
        EnumMap<Status, Integer> ticketCounts = new EnumMap<>(Status.class);

        ticketCounts.put(Status.NEW, 12);
        ticketCounts.put(Status.DONE, 47);
        ticketCounts.put(Status.IN_PROGRESS, 5);

        // Iterates in enum declaration order, NOT insertion order
        ticketCounts.forEach((status, count) ->
            System.out.println(status + " -> " + count));
        // NEW -> 12
        // IN_PROGRESS -> 5
        // DONE -> 47

        // getOrDefault / merge work exactly like HashMap
        ticketCounts.merge(Status.REVIEW, 1, Integer::sum);
    }
}

Real interview-favorite pattern: grouping with EnumMap

enum Suit { CLUBS, DIAMONDS, HEARTS, SPADES }
record Card(Suit suit, String rank) {}

Map<Suit, List<Card>> bySuit = deck.stream()
        .collect(Collectors.groupingBy(
                Card::suit,
                () -> new EnumMap<>(Suit.class), // 3-arg groupingBy: pick the map impl
                Collectors.toList()));

This is a common way EnumMap shows up in real code and interviews: swapping the default HashMap supplier in Collectors.groupingBy for an EnumMap when the grouping key is an enum.

4. How they work internally

EnumSet

Two package-private implementations, chosen automatically:

  • RegularEnumSet — enum has ≤ 64 constants. Backed by a single long bitmask; each bit position = one ordinal.
  • JumboEnumSet — enum has > 64 constants. Backed by a long[].

add(x) is bits |= (1L << x.ordinal()). contains(x) is a single AND + compare. Union/intersection/difference are single bitwise OR/AND/AND-NOT ops across the whole set — this is why bulk operations are so fast.

EnumMap

Backed by a plain Object[] array, sized to enumType.getEnumConstants().length. A key's slot is simply array[key.ordinal()] — no hashing, no bucket, no collision handling. A parallel boolean/sentinel tracks which slots are populated (absent vs. null-valued).

Because there's no hashing step at all, both get and put are true O(1) with a lower constant factor than HashMap.

6. Pitfalls & gotchas

  • No-arg constructor doesn't exist for EnumMap. You must pass SomeEnum.class (or copy from an existing EnumMap) — this is how it knows the array size and element order, since type erasure removes generic info at runtime.
  • Null keys throw NPE immediately on put/add — unlike HashMap, which tolerates one null key.
  • Adding constants to the enum later is safe — no rehashing needed, unlike HashMap where growth means resize + rehash.
  • EnumSet has no public constructor — always created via static factories (of, range, allOf, etc.), which is itself a common "why" interview question.
  • Comparing across different enum types in the same generic context is a compile error — EnumMap/EnumSet are strictly single-enum-type, which HashMap/HashSet don't enforce.

7. Interview Q&A

Q: Why use EnumMap instead of HashMap for enum keys?
A: EnumMap indexes directly by ordinal into an array — no hashing, no collisions, lower memory footprint, and it iterates in natural enum order. It's a strictly better fit whenever the key type is a known enum.
Q: How is EnumSet implemented under the hood?
A: As a bitmask — a single long (RegularEnumSet) if the enum has ≤64 constants, or a long[] (JumboEnumSet) otherwise. Each bit corresponds to one ordinal position.
Q: Why can't you just call new EnumSet<Day>()?
A: EnumSet is abstract with no public constructor by design — you're forced through factory methods (of, range, allOf, noneOf, complementOf) that also select the right internal implementation (Regular vs Jumbo) based on the enum's size.
Q: What happens if you put a null key into an EnumMap?
A: It throws NullPointerException immediately — unlike HashMap, EnumMap does not support null keys (or null elements in EnumSet).
Q: Is EnumMap's iteration order guaranteed?
A: Yes — it always iterates in the natural order of the enum, i.e., the order constants are declared in the enum's source, which corresponds to ascending ordinal().
Q: When would you deliberately avoid EnumMap/EnumSet?
A: When the key/element type isn't a single fixed enum — e.g., a heterogeneous key type, a key type that's decided at runtime/pluggable, or when you need null keys. Also not useful for enums with an enormous number of constants where a sparse map might actually save memory over an array sized to all constants (rare in practice).
Q: Are EnumMap/EnumSet thread-safe?
A: No, same as HashMap/HashSet. Wrap with Collections.synchronizedMap(...) / synchronizedSet(...), or externally synchronize, for concurrent use.
Q: Give a practical real-world use case for each.
A: EnumSet — representing a set of permission flags or feature toggles (replacing bitwise int flags). EnumMap — a state machine's transition table, or grouping/counting results by a status enum (e.g., ticket counts by Status).
