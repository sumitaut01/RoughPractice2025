Handling Alerts in Selenium

Native JS dialogs (alert / confirm / prompt) — the Alert interface, wait strategies, and common pitfalls

Overview

Why Alerts Are Different

JavaScript alerts (alert(), confirm(), prompt()) are native OS-level dialogs rendered outside the DOM. They can't be located with normal WebElement locators — Selenium instead exposes a dedicated Alert interface, accessed via driver.switchTo().alert().

Basics

Basic Alert Handling

import org.openqa.selenium.Alert;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.support.ui.WebDriverWait;
import org.openqa.selenium.support.ui.ExpectedConditions;
import java.time.Duration;

// Trigger the action that causes the alert
driver.findElement(By.id("alertButton")).click();

// Switch control to the alert
Alert alert = driver.switchTo().alert();

// Read the alert text
String alertText = alert.getText();
System.out.println("Alert says: " + alertText);

// Accept (OK) or Dismiss (Cancel)
alert.accept();   // clicks OK
alert.dismiss();  // clicks Cancel

Handling a Prompt (text input alert)

Alert alert = driver.switchTo().alert();
alert.sendKeys("some input text");
alert.accept();
Best Practice

Waiting for the Alert

Alerts don't always appear instantly. Calling switchTo().alert() immediately can throw NoAlertPresentException. Always wait explicitly: 

WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
Alert alert = wait.until(ExpectedConditions.alertIsPresent());
alert.accept();

Handling Unexpected Alerts Gracefully

Wrap in try-catch when an alert may or may not appear:

try {
    Alert alert = driver.switchTo().alert();
    alert.accept();
} catch (NoAlertPresentException e) {
    // no alert appeared, continue normally
}
Driver Config

Setting Unexpected Alert Behavior at Driver Level

If alerts pop up unpredictably during a run (e.g. session-timeout warnings), configure Chrome to auto-dismiss/accept them so they don't break your flow: 

ChromeOptions options = new ChromeOptions();
options.setCapability("unhandledPromptBehavior", "dismiss");
// options: "accept", "dismiss", "accept and notify", "dismiss and notify", "ignore"
Reference

Key Gotchas

Issue Cause / Fix
NoAlertPresentException Alert not yet rendered — use WebDriverWait with alertIsPresent()
UnhandledAlertException on next command An alert was left open from a previous step and blocks all further interaction — always resolve alerts immediately
Alert not detected at all It might be a custom JS modal (a styled <div>), not a native window.alert() — those are handled like normal DOM elements, not via the Alert interface
Alert appears during page load Some apps fire alerts via beforeunload — handle with the unhandledPromptBehavior capability
Parallel execution note: in a hybrid framework running tests in parallel, each thread's WebDriver instance is independent, so alert handling is naturally thread-safe as long as driver instances aren't shared — ThreadLocal<WebDriver> handles that already if that's how the framework is structured.
