Git Reset vs Git Revert

Understand the difference visually with examples and commit history changes.

git reset

Rewrites History

git reset moves the branch pointer backward. Commits may disappear from history.

Before Reset

A
B
C
D
git reset --hard B

After Reset

A
B
Commits C and D are removed from branch history. This changes commit history.
Use when:
  • You want to undo local commits
  • Commits are NOT shared with others
  • You want a clean history

Example

# Last commits A -> B -> C -> D (HEAD) # Move HEAD back to B git reset --hard B

Now your branch history becomes:

A -> B (HEAD)

Dangerous on shared branches.

git revert

Preserves History

git revert creates a NEW commit that undoes previous changes.

Before Revert

A
B
C
D
git revert D

After Revert

A
B
C
D
R
A new commit R is created that reverses changes introduced by D.
Use when:
  • Commits are already pushed/shared
  • You want safe undo operations
  • You need complete audit history

Example

# Existing history A -> B -> C -> D (HEAD) # Revert commit D git revert D

New history becomes:

A -> B -> C -> D -> R (HEAD)

Safe for shared branches.

Feature git reset git revert
Changes commit history? Yes No
Safe for shared branches? No Yes
Creates new commit? No Yes
Best for Local cleanup Undoing public commits
Can lose commits? Yes No

Quick Mental Model

RESET = Pretend commit never happened REVERT = Add another commit to cancel previous commit

Common Commands

# Undo last commit but keep code git reset --soft HEAD~1 # Undo last commit and remove changes git reset --hard HEAD~1 # Safely undo a pushed commit git revert HEAD
